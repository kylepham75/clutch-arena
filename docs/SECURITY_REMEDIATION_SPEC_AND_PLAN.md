# Clutch Arena Security Remediation Specification & Implementation Plan

## 1. Purpose and Scope

This document defines the security architecture constraints, trust boundaries, operational prerequisites, and remediation plan for Clutch Arena across Next.js App Router API routes, Supabase Postgres Row-Level Security (RLS) policies, AI cost-governance quotas, document parsers, and Cloudflare Durable Object realtime rooms.

## 2. Threat Model and Trust Boundaries

1. **Browser Client Boundary (Untrusted):**
   - HTTP headers (`Origin`, `X-Forwarded-For`, `X-Forwarded-Host`, `X-Forwarded-Proto`, `CF-Connecting-IP`, `X-Test-Tier`), multipart/chunked stream sizes without `Content-Length`, URL hash packs (`#pack=`), JSON `fileSha256` claims, and WebSocket room messages are treated as attacker-controlled until verified server-side.
   - Browser bundles must never import Node built-ins (`node:zlib`) or server secrets (`SUPABASE_SERVICE_ROLE_KEY`, AI provider keys, webhook secrets). Pure XML/OMML slide extraction for browser preview lives in [pptx-xml.ts](../lib/ingestion/pptx-xml.ts).
2. **Next.js API Boundary (Authoritative Application Logic):**
   - Every state-changing or paid-inference route enforces origin checks via [`isAllowedOrigin`](../lib/utils.ts), Bearer authentication via [`verifyAuthToken`](../lib/auth/server-guard.ts) or [`verifyNotesAccess`](../lib/auth/notes-guard.ts), actor-locked throttling, bounded body stream reading before JSON/multipart decoding, and rolling USD quota reservation before upstream AI calls.
3. **Database Boundary (`lib/supabase/server.ts` & Postgres RLS):**
   - [`getSupabaseUserServerClient`](../lib/supabase/server.ts) uses the anonymous key plus the caller's Bearer JWT so Postgres RLS evaluates as that user.
   - [`getSupabaseAdminClient`](../lib/supabase/server.ts) uses `SUPABASE_SERVICE_ROLE_KEY` exclusively for privileged backend tasks (webhooks, quota ledgers, account cascade deletion, telemetry writes).
   - [`public.is_service_role()`](../supabase/migrations/20261119_security_audit_remediation.sql) uses `SECURITY INVOKER` with a locked `search_path` so caller sessions cannot escalate to `postgres` privileges during RLS evaluation.
4. **External Payment Webhooks (Polar & PayOS):**
   - Webhooks validate cryptographic signatures and freshness windows over bounded `128 KB` request streams before mutating entitlements, enforce tier-rank monotonicity so delayed lower-tier notifications cannot overwrite higher-tier active subscriptions, block replay on terminal statuses (`expired`, `revoked`, `refunded`, `cancelled`), and propagate cancellations/refunds into profile downgrade triggers.
5. **Cloudflare Durable Object Boundary (`party/arena.ts` & `party/worker.ts`):**
   - Internal control HTTP methods (`/init` and lobby directory mutations) fail closed whenever `PARTYKIT_INTERNAL_SECRET` is unset and compare secrets in constant time via `timingSafeMatch`.
   - WebSocket `INIT_ROOM` requires server-issued authorization, HTTP `/init` validates payloads with `createRoomSchema`, room tier caps clamp against host tier, CORS checks explicit allowlists, and `live` round broadcasts mask answer correctness (`bestStreak`, `correctIndex`, `explanation`) until round close.

## 3. Core Architecture Invariants

- **Rolling Quota Lifecycle & Privacy:** Uncached AI/OCR calls check cache first (`0%` quota cost), acquire an actor-scoped distributed lock (`withActorQuotaLock` in Redis + process lock map), reserve estimated spend against rolling primary (`24h`/`72h`), guard (`168h`/`720h`), and cycle COGS ceilings, settle observed usage on completion or partial SSE emission, and roll back unused holds on failure or abort. Raw USD values remain server-side; HTTP responses expose only percentages and booleans via `toClientQuota()`.
- **Cache Isolation:** Paid (`v2`, `notes-v2`) and free/degraded cache tiers never downgrade paid users. Read/write helpers clone cached entries (`cloneCacheValue`) so free-tier `distractorRationale` stripping never mutates shared in-memory objects. Unverified JSON `fileSha256` values map only inside per-actor storage and write `NULL` to global database SHA indexes.
- **Parser Resource Bounds:** Archive validators (`validateDocxArchive`, `validatePptxArchive`) inspect local ZIP boundaries and bound actual raw `DEFLATE` expansion with `inflateRawSync(..., { maxOutputLength })` before `JSZip` or `mammoth` decodes XML. PPTX XML scanning uses a single-pass stack scanner (`scanXmlTagBlocks`) with abort checks instead of nested `[\s\S]*?` backtracking regexes. PDF extraction caps image XObject buffers (`4 MB`), canvas area (`16 MB`), screenshot aspect height (`1536 px`), skips eager image scans when Vision OCR is disabled without `rescanPages`, and bills Gemini fallback usage explicitly.
- **Error Sanitization:** Routes return structured error codes and generic user-facing messages on `5xx` failures while keeping stack traces and upstream vendor payloads in server logs.
- **Bilingual & Visual Contracts:** UI copy, `<MathText />` KaTeX styles, Hallucination Shield v3 `"MARK, don't block"` behavior, and parity between `party/arena.ts` and `lib/multiplayer/room-manager.ts` remain preserved.

## 5. Rollout and Migration Runbook

1. **Apply SQL Migration First:** Run [20261119_security_audit_remediation.sql](../supabase/migrations/20261119_security_audit_remediation.sql) against Supabase Postgres. It is idempotent (`CREATE OR REPLACE FUNCTION`, `DROP TRIGGER IF EXISTS ... CREATE TRIGGER`, `ALTER COLUMN SET DEFAULT`, zero-row backfill `UPDATE`) and performs four actions:
   - Replaces `public.is_service_role()` with `SECURITY INVOKER` + explicit `search_path`.
   - Sets `user_quota_ledgers.cogs_ceiling_usd` default to `0.08` and repairs existing rows with `<= 0` ceilings.
   - Adds `on_auth_user_deleted_cleanup` trigger on `auth.users` to purge `user_quota_ledgers`, `pilot_telemetry`, and `user_concept_mastery`.
   - Adds `on_subscription_revoked_sync_profile` trigger on `user_subscriptions` to downgrade `profiles` and `user_profiles` when subscriptions become `revoked`, `refunded`, or `cancelled`.
2. **Set Required Environment Variables Before Next Deploy:**
   - Next.js / Vercel: `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_APP_URL`, `ALLOWED_ORIGINS`, `SUPABASE_SERVICE_ROLE_KEY`, `PARTYKIT_INTERNAL_SECRET`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, `POLAR_WEBHOOK_SECRET`, and (only if testing via signed header) `TEST_TIER_OVERRIDE_SECRET`. Leave `TRUST_CLOUDFLARE_HEADERS=false` unless origin IP checks are bypassed exclusively behind verified Cloudflare proxy headers.
   - Cloudflare Worker (`wrangler secret` / vars): `PARTYKIT_INTERNAL_SECRET`, `NEXT_PUBLIC_SITE_URL`, `NEXT_PUBLIC_APP_URL`, `ALLOWED_ORIGINS`, `NODE_ENV=production`.
3. **Deploy Order:** Deploy Supabase migration -> set Worker secrets & deploy `party/worker.ts` -> set Vercel env vars & deploy Next.js build -> verify `/api/quota`, webhook health, and realtime room `/init`.
